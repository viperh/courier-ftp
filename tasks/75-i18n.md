# T75 — Internationalisation

**Phase:** G App-level · **Depends on:** T50 · **Crate:** `courier-ftp` (+ core error messages) · **FEATURES.md:** §3 (translated into many languages)

## Goal

Infrastructure for translating the UI, with English complete and at least one
other language as proof.

## Scope

1. Choose a system: **Fluent** (`fluent` + `fluent-templates`, compile-time embedded `.ftl` files) — handles plurals ("1 file" / "3 files") properly. *(Default chosen; alternative `rust-i18n` if Fluent proves heavy.)*
2. Message keys for every user-visible UI string (dialogs, status bar, help, errors shown to user). Protocol log lines from servers are **not** translated; our Status lines are.
3. Language selection: `interface.language` = `auto` (from `LANG`/`LC_ALL`/OS locale via `sys-locale`) or explicit code; fallback to English for missing keys.
4. Core crates stay language-neutral: errors carry structured data; the UI formats them through Fluent.
5. Width-aware layout: translated strings may be longer — use unicode width (`unicode-width`) in all layout calculations; test with a pseudo-locale (`en-XA` that pads and accents strings) to catch truncation bugs.
6. Contributor docs: how to add a language (`docs/translating.md`).
7. Second language: **ask the user which** (e.g. Romanian or German) before implementing.

## Acceptance criteria

- [ ] No hard-coded user-visible English strings left in UI code (grep-based CI check for string literals in render paths, with an allowlist).
- [ ] Pseudo-locale renders without overflow at 80×24.
- [ ] Plural forms correct.

## Tests

- Snapshot tests in `en` and pseudo-locale.
