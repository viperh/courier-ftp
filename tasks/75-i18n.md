# T75 — Internationalisation

**Phase:** G App-level · **Milestone:** M9 · **Depends on:** T50 · **Crate(s):** `courier-ftp` (`i18n` module, `i18n/` assets, all UI components), `courier-ftp-core` (`text` module, `LogMessage`) · **Decisions:** D10 · **FEATURES.md:** §3 (the interface is translated into many languages)

## Goal

Every user-visible UI string goes through Fluent message files, so courier-ftp can be
translated without touching code. English (`en-US`) is complete, a generated
pseudo-locale (`en-XA`) catches truncation and width bugs, and one more real language
proves the pipeline (which one is an open question for the owner). CI fails on missing
keys, stale translations, broken plurals and new hard-coded UI strings.

## Context

- T50 owns the main screen, the help overlay and the theme; all components (T51–T69,
  T72–T74, T90) render English literals until this task.
- T04's `LogMessage { time, session, kind, text: String }` carries status lines produced by
  core code (e.g. T07's `Resolving address of …`, `Connecting to …`) and server text
  (commands, replies, raw listings).
- T02's `courier_ftp_core::Error` variants hold English detail strings from servers/OS.
- T05 has `interface.language` (`"auto"`). T68 shows it in Settings → Interface.
- T70 defines the CLI; this task adds `--lang`.
- T00 runs `cargo test` in `test-local-only`/`test-os`; this task adds an `i18n` job.

## Technical specification

### Types and APIs

**Library choice** (decided): `i18n-embed` (features `fluent-system`, `desktop-requester`)
+ `i18n-embed-fl` (`fl!` macro that checks message ids and arguments against the
fallback `.ftl` **at compile time**) + `rust-embed` (assets compiled into the binary) +
`fluent-langneg`, `unic-langid`, `sys-locale`, `unicode-width`. `fluent-syntax` is a
dev-dependency for the CI tests. This replaces the earlier `fluent-templates` idea because
the compile-time key check removes a whole class of runtime misses.

`crates/courier-ftp/src/i18n.rs`:

```rust
#[derive(rust_embed::RustEmbed)]
#[folder = "i18n/"]
pub(crate) struct Localizations;

/// The process-wide loader. `use_isolating` is off: terminals render the Unicode
/// FSI/PDI marks Fluent would insert around placeables as garbage.
pub(crate) static LOADER: LazyLock<FluentLanguageLoader>;

/// `fl!("queue-summary", count = 3)` — thin wrapper around `i18n_embed_fl::fl!(LOADER, …)`.
#[macro_export] macro_rules! fl { … }

pub(crate) const FALLBACK: &str = "en-US";
pub(crate) const PSEUDO: &str = "en-XA";

/// Where the language choice came from (shown in Settings and `--version` debug output).
#[derive(Debug, Clone, PartialEq, Eq)]
pub(crate) enum LanguageSource { CliFlag, Env, Setting, Os, Fallback }

/// Resolves and loads the UI language. Pure apart from `os_locales`.
pub(crate) fn select_language(cli: Option<&str>, env: Option<&str>, setting: &str,
    os_locales: &[String]) -> (LanguageIdentifier, LanguageSource);
pub(crate) fn apply_language(lang: &LanguageIdentifier) -> Result<(), I18nError>;
/// Embedded languages with their self-names (`language-self-name` key), `en-XA` excluded
/// unless `include_pseudo`.
pub(crate) fn available_languages(include_pseudo: bool) -> Vec<(LanguageIdentifier, String)>;
/// Renders a core `Localizable` with the current loader.
pub(crate) fn tr(msg: &Localizable) -> String;
/// User-facing text for a core error.
pub(crate) fn error_message(err: &courier_ftp_core::Error) -> String;

#[derive(Debug, thiserror::Error)]
pub(crate) enum I18nError {
    #[error("invalid language tag {0:?}")] InvalidTag(String),
    #[error("cannot load translations: {0}")] Load(String),
}
```

`crates/courier-ftp/src/ui/text.rs` (width helpers used by every component):

```rust
pub(crate) fn width(s: &str) -> usize;                                  // unicode-width
pub(crate) fn truncate(s: &str, max: usize) -> Cow<'_, str>;           // appends '…', never splits a grapheme
pub(crate) fn pad_right(s: &str, width: usize) -> Cow<'_, str>;
pub(crate) fn truncate_middle(s: &str, max: usize) -> Cow<'_, str>;    // paths: "/var/…/file"
```

**Core stays language-neutral** — `courier_ftp_core::text`:

```rust
/// A message id plus arguments, rendered by the UI. Core never formats user text itself.
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub struct Localizable { pub id: Cow<'static, str>, pub args: Vec<(Cow<'static, str>, ArgValue)> }

#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub enum ArgValue { Str(String), Int(i64), Float(f64) }

/// `loc!("status-connecting", addr = addr.to_string())`
#[macro_export] macro_rules! loc { … }

/// Text of a log message (changes T04's `LogMessage::text: String`).
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub enum LogText {
    /// Server or protocol text, shown verbatim (commands, replies, raw listings, server errors).
    Raw(String),
    /// Our own message, translated by the UI.
    Msg(Localizable),
}
```

`LogMessage.text` becomes `LogText`; `LogKind::Command`, `Response`, `ListingRaw` always
carry `Raw`; `Status`, `Error` and `Debug(n)` produced by our code carry `Msg`; an `Error`
line whose detail is server text uses a `Msg` with the server text as a `Str` argument
(`error-server-reply = Server replied: { $reply }`). Debug-level (`Debug(3|4)`) messages
may stay `Raw` English (developer detail; documented exception).

CLI (T70) gains:

```rust
/// UI language for this run, e.g. "de" or "en-XA" (pseudo-locale)
#[arg(long, value_name = "LANG", env = "COURIER_FTP_LANG")]
pub lang: Option<String>,
```

### Behaviour

**Language selection** (at startup and when the setting changes), first match wins:
1. `--lang` (T70), then `COURIER_FTP_LANG`.
2. `interface.language` when not `"auto"`.
3. OS locales: `sys_locale::get_locales()` (Unix: `LC_ALL`, `LC_MESSAGES`, `LANG`;
   macOS/Windows: system preference list). POSIX forms are normalised:
   `de_DE.UTF-8@euro` → `de-DE`; `C`, `POSIX`, empty → skipped.
4. `en-US`.

Each candidate is negotiated against the embedded languages with
`fluent_langneg::negotiate_languages(…, NegotiationStrategy::Filtering)` (`de-AT` → `de`,
`pt` → `pt-BR` if only that exists). A candidate with no match falls through to the next
step. An invalid tag from `--lang`/env → usage error exit 2 (`I18nError::InvalidTag`);
from the setting → warning in the app log + fallback (T05 validation rule).
`en-US` is always loaded as the fallback bundle, so a key missing from the selected
language shows the English text (never the key id).

**Runtime switch**: changing `interface.language` in Settings (T68) calls
`apply_language` and triggers a full redraw; no restart. Components must not cache
translated strings across frames (rule in `docs/translating.md`; enforced by snapshot
tests that switch language mid-test).

**What is translated / not translated:**

| Translated | Not translated |
|---|---|
| All TUI text: panes, titles, column headers, dialogs, buttons, forms, help overlay, status bar, toasts, prompts (T69), wizard pages and hints (T72), update notice (T74), our `Status:`/`Error:` lines | Server text: commands, replies, raw listings, server error details, banners, file and directory names |
| Action names in the help overlay (`action-<name>` keys) | Key names (`F5`, `Ctrl-s`), config keys, URLs, paths |
| Error messages shown to users (`error_message`) | Application log (tracing), crash reports, CLI `--help`, man page, CLI error messages on stderr |
| Session log file content (it renders the same messages as the log pane, T71) | Date/size formats (user-configured patterns, T05) and month names |

**Plurals**: every message that depends on a count uses a Fluent select on a
**number** argument, so CLDR rules (via `intl_pluralrules`) pick the form:

```ftl
# $count (Number) - number of files in the queue
# $size (String) - total size, already formatted (e.g. "8 KiB")
queue-summary =
    { $count ->
        [one] Queue: { $count } file, { $size }
       *[other] Queue: { $count } files, { $size }
    }
```

Numbers that need grouping or units (sizes, speeds, durations, dates) are formatted by
our formatters (T05 `size_format`, `thousands_separator`, `date_format`) and passed as
strings; Fluent formats only plain counts.

**Pseudo-locale `en-XA`**: generated from `en-US` by the test `pseudo_locale_is_fresh`
(writes the file when `COURIER_FTP_BLESS=1`, T00 convention). Transformation of every
text element (placeables, variables, selectors and attribute names untouched):
ASCII letters mapped to accented look-alikes (`a→á e→é i→í o→ó u→ú A→Á …`, all width 1),
each message value and attribute wrapped in fullwidth brackets `［…］` (width 2 each),
and `~` padding appended to reach `ceil(1.4 × original width)`. It is never offered in the
Settings picker; select it with `--lang en-XA`.

**Width-aware layout**: all components measure displayed text with `ui::text::width`
and cut it with `truncate`/`truncate_middle` (`…`); `str::len()` is never used for
layout. Dialog widths are computed from the widest translated label/button, capped at the
terminal width minus 4, and wrap text otherwise (T52).

### Data formats and configuration

File layout:

```
crates/courier-ftp/i18n.toml                       fallback_language = "en-US", [fluent] assets_dir = "i18n"
crates/courier-ftp/i18n/en-US/courier-ftp.ftl      source of truth
crates/courier-ftp/i18n/en-XA/courier-ftp.ftl      generated pseudo-locale (checked in)
crates/courier-ftp/i18n/<lang>/courier-ftp.ftl     translations (one file per language)
scripts/check-i18n-literals.py                     hard-coded string scan (+ --self-test)
scripts/i18n-allowlist.txt                         reviewed exceptions, "path:line-content" per line
docs/translating.md                                contributor guide
```

**Key naming** (kebab-case `area-element[-detail]`; ids are stable once released):

| Prefix | Use | Example |
|---|---|---|
| `app-` | app name, window-level | `app-loading` |
| `common-` | shared words/buttons | `common-ok`, `common-cancel`, `common-back` |
| `status-` | our status-log lines and status bar segments | `status-connecting`, `status-bar-queue` |
| `error-` | user-facing error texts (one per `Error` variant + specific cases) | `error-timeout` |
| `pane-`, `tree-`, `log-`, `queue-` | panes | `pane-local-title`, `queue-tab-failed` |
| `dialog-` | generic dialogs (T52) | `dialog-confirm-delete` |
| `site-manager-`, `bookmarks-`, `search-`, `compare-`, `filters-` | feature screens | `site-manager-tab-advanced` |
| `settings-` | Settings sections and fields: `settings-<section>-<field>` with `.help` attribute | `settings-transfers-max-concurrent` |
| `vault-`, `sync-`, `trust-` | vault/unlock, sync/teams, trust prompts | `vault-unlock-button` |
| `wizard-` | network wizard (T72), one `wizard-hint-<hint>` per `Hint` | `wizard-hint-incoming-blocked` |
| `update-`, `backup-` | T74, T73 | `update-available` |
| `action-` | one per `Action` variant, for the help overlay | `action-copy` |
| `language-self-name` | the language's own name, required in every file | `Deutsch` |

Rules: related strings use attributes (`.title`, `.help`, `.placeholder`, `.button`); the
term `-app-name = courier-ftp` is used instead of the literal name; every variable is
documented in a `# $name (Type) - meaning` comment above the message; no message
concatenation in code (whole sentences are one message).

Settings: `interface.language` (string, default `"auto"`; `"auto"` or a BCP 47 tag that is
an embedded language). Env `COURIER_FTP_LANG`. New workspace deps: `i18n-embed`,
`i18n-embed-fl`, `rust-embed`, `fluent-langneg`, `unic-langid`, `sys-locale`,
`unicode-width` (may already exist via ratatui), dev `fluent-syntax`.

### Errors

- `I18nError::InvalidTag` from `--lang`/`COURIER_FTP_LANG` → T70 usage error, exit 2.
- `I18nError::Load` (corrupt embedded file — only possible through a build error, since
  CI parses every file): logged at `error`, the app continues with `en-US`.
- A message that fails to format at runtime (wrong argument type in a translation) falls
  back to the `en-US` message; logged once per key at `warn` (key id only).
- `error_message` covers every `courier_ftp_core::Error` variant (exhaustive `match`, no
  wildcard, so a new variant fails to compile until it has a key).

### Security and logging

- Translations are compiled in; no runtime loading of `.ftl` files from disk (no injection
  of terminal escape sequences through a dropped-in file). A test asserts no `.ftl` text
  contains C0/C1 control characters except newline.
- Arguments that carry server text or file names are escaped by the T71
  `escape_controls` helper **before** being passed to Fluent.
- Logging: the app log stays English and never logs rendered UI strings; the chosen
  language and its source are logged at `info` (`ui language: de (os)`), which contains
  no personal data.

## Implementation steps

1. Add deps, `i18n.toml`, `i18n.rs` (loader, `fl!`, `select_language`, `apply_language`),
   `--lang`/`COURIER_FTP_LANG` in the T70 CLI, `ui/text.rs` width helpers. Unit tests.
2. Core: `text` module (`Localizable`, `ArgValue`, `loc!`), `LogText` in `LogMessage`;
   convert core producers (T07, T10–T15, T20–T22, T41–T45) to `loc!` ids; the UI renders
   via `tr`. Core tests assert ids/args instead of English text.
3. `error_message` for every `Error` variant.
4. Convert components area by area (shell/status bar/help → panes → dialogs → Site
   Manager → settings → vault/sync → wizard/backup/update), each step adding its keys to
   `en-US` and keeping snapshots identical in `en-US`.
5. CI tests in `crates/courier-ftp/tests/i18n.rs` (parse, unknown keys, variables,
   plurals, usage, coverage, controls, pseudo freshness) and the pseudo-locale generator.
6. `scripts/check-i18n-literals.py` with `--self-test` and the allowlist; CI job `i18n`
   in `ci.yml` (runs the script; the Rust tests already run in the test jobs); add it to
   the required checks in `CONTRIBUTING.md`.
7. `en-XA` snapshot tests for every view at 80×24 and the overflow checker.
8. `docs/translating.md`.
9. Second language (after the owner answers the open question): full translation, 100 %
   coverage, native-speaker review noted in the PR.

## Out of scope

- Right-to-left scripts and bidirectional layout.
- Localised number grouping, month names and date formats beyond the user's T05 patterns.
- Translating the CLI help, man page, application log and crash reports.
- Translations other than `en-US`, `en-XA` and the one second language (community
  contributions later, following `docs/translating.md`).
- A translation management platform (Weblate, Crowdin).
